# audio.cpp portable updater

`updater.ps1` implements the first update-protocol version described in the
online-update release plan. It accepts these public command-line forms:

```powershell
.\update.bat --check
.\update.bat --apply
.\update.bat --dry-run
.\update.bat --manifest C:\path\to\manifest-v0.2.1.json --dry-run
```

The updater only installs files listed by a component archive's `files.json`.
It always protects model, voice, output, log, API-key, and user-config paths,
even if a remote manifest omits a preserve rule.

Protocol 1.1 also supports two optional component types:

- `python-deps`: offline, hash-locked CPython 3.11 wheels with explicit package
  path backup and rollback metadata. Torch, Python itself, CUDA packages, and
  arbitrary indexes or URLs are rejected.
- `updater`: a signed updater snapshot. The running updater validates and stages
  it, then `apply-update.ps1` replaces updater files after the original process
  exits, self-checks the new updater, and resumes the same manifest.

Before publishing, place the release minisign public key in `public-key.txt`
and bundle the official `minisign.exe` beside `updater.ps1`. Keep the minisign
secret key outside the repository and outside the portable package.

Release assets are generated by `scripts/build_update_release.ps1`. The
self-contained updater acceptance test is `tests/updater/run_tests.ps1`.

`update.bat` is intentionally only a launcher. Argument parsing, online checks,
downloads, validation, locking, installation, health checks, and rollback all
live in the PowerShell scripts so updater maintenance does not require batch
logic changes.

Generate the one-time overlay patch for existing `0.2.0` bundles with:

```powershell
.\scripts\build_updater_bootstrap.ps1 `
  -Version 0.2.0 `
  -MinisignBinary C:\release-tools\minisign.exe `
  -PublicKeyPath C:\release-tools\audio-cpp.pub
```

Generate signed stable update assets after building and testing the portable
CPU/CUDA executables with:

```powershell
.\scripts\build_update_release.ps1 `
  -Version 0.2.1 `
  -MinisignSecretKey C:\secure\audio-cpp.key `
  -MinisignPublicKey C:\release-tools\audio-cpp.pub `
  -MinisignPath C:\release-tools\minisign.exe `
  -Stable
```

The default compatibility range is `>=0.2.0`, so bundles that receive the
one-time 0.2.0 bootstrap remain eligible for later 0.3.x and newer releases.
Use `-SupportedFrom` only when a future release intentionally drops an older
portable layout.

When Python dependencies change, prepare a directory with this layout and pass
it as `-PythonDepsSource`:

```text
python-deps-v0.2.1/
  wheels/*.whl
  requirements-update.txt
  before-install.json
  after-install-checks.json
```

`requirements-update.txt` must contain one exact `name==version` requirement
per line with at least one `--hash=sha256:<64 hex>` value. It cannot contain
indexes, URLs, editable installs, environment markers, Torch, CUDA, or Triton.

`before-install.json` declares paths that must be backed up for installed
packages being upgraded:

```json
{
  "schema": 1,
  "packages": [
    {
      "name": "example-package",
      "version": "1.0.0",
      "paths": [
        "venv/Lib/site-packages/example_package",
        "venv/Lib/site-packages/example_package-1.0.0.dist-info"
      ]
    }
  ]
}
```

`after-install-checks.json` declares the exact target version and every package
path that must be removed during rollback before the old paths are restored:

```json
{
  "schema": 1,
  "packages": [
    {
      "name": "example-package",
      "version": "1.1.0",
      "paths": [
        "venv/Lib/site-packages/example_package",
        "venv/Lib/site-packages/example_package-1.1.0.dist-info"
      ]
    }
  ]
}
```

Build a release containing dependency and updater components with:

```powershell
.\scripts\build_update_release.ps1 `
  -Version 0.2.1 `
  -PythonDepsSource C:\release-work\python-deps-v0.2.1 `
  -IncludeUpdater `
  -UpdaterMinisignBinary C:\release-tools\minisign.exe `
  -MinimumUpdater 1.1.1 `
  -MinisignSecretKey C:\secure\audio-cpp.key `
  -MinisignPublicKey C:\release-tools\audio-cpp.pub `
  -MinisignPath C:\release-tools\minisign.exe `
  -Stable
```

Omit `-PythonDepsSource` when dependencies did not change. Omit
`-IncludeUpdater` when updater files did not change. The release builder always
generates app, core-cpu, and core-cuda snapshots.

For every stable online release, publish the generated `stable.json`, signed
manifest, manifest signature, and all component ZIPs in the same non-draft,
non-prerelease GitHub Release, and mark that Release as latest. The updater's
permanent channel URL is GitHub's `releases/latest/download/stable.json`; if the
latest Release omits `stable.json`, online checks will correctly fail instead
of installing an ambiguous payload.

After publishing, extract the bootstrap over a clean 0.2.0 portable copy and
run `update.bat --check`. Do not distribute the bootstrap until that command
reports the newly published target version through the default channel URL.

The bootstrap ZIP is the small net-disk patch described by the release plan.
It contains the updater and local version metadata, but no models, Python
environment, application payload, or runtime binaries.
